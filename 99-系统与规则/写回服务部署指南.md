## 一、需要什么

1. 一个腾讯云账号（你之前部署 SCM 中转站用的那个）
2. GitHub 令牌（对 `WenXue-10/CET6-Dashboard` 有写权限；可与 SCM 中转站用同一个令牌）
3. 一个自己定的"钥匙"（APP_KEY，随便一串字母数字）

## 二、部署步骤（约 5 分钟）

1. 打开[腾讯云·云函数控制台](https://console.cloud.tencent.com/scf) → **新建** → 选择**「Web 函数」**（不是事件函数）。
2. 运行环境选 **Node.js 16 或更高版本**；函数名如 `cet6-bridge`。
3. 把 `cet6_bridge_scf.js` 的全部内容粘到 **index.js**（不要动 `scf_bootstrap`）。
4. 在**环境变量**里添加两个：
   - `GITHUB_TOKEN` = 你的 GitHub 令牌（建议新建一个只用于本仓库的令牌：GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens**，仓库选 `WenXue-10/CET6-Dashboard`，权限勾 `Contents: Read and write`）
   - `APP_KEY` = 你自定的钥匙（例如 `cet6-2026-xxxx`，记下来）
5. 点击**部署**，然后在「触发管理」里复制函数访问地址（形如 `https://xxx.ap-shanghai.tencentscf.com`）。
6. **验证**：用下面命令测一下（把地址和钥匙换成你的）：
   ```
   在浏览器控制台或 Postman 里 POST：
   地址? （直接 POST，无需路径）
   body: {"key":"你的APP_KEY","action":"checkin"}
   ```
   返回 `{"ok":true}` 即成功。

两种方式任选其一：

- **方式 A（推荐）**：编辑 `site_assets/app.js` 顶部的：
  ```js
  var BRIDGE = { url: "https://1473705102-38601bi8ym.ap-shanghai.tencentscf.com", key: "0606" };
  ```
  改完运行 `update_site.ps1` 重新构建推送即可（当前网页端已填好，无需再改）。

- **方式 B（不改代码，本机测试用）**：在浏览器控制台执行：

  ```js
  localStorage.setItem("cet6_bridge", JSON.stringify({url:"https://1473705102-38601bi8ym.ap-shanghai.tencentscf.com", key:"0606"}));
  ```
  刷新页面即生效（仅当前设备有效）。

1. **复制内容** → 粘贴到豆包，对我说"帮我录进知识库：……"，我在电脑端帮你写进去；

## 六、故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 保存提示"服务未连接" | 云端函数没部署好，或 BRIDGE.url 没填对；检查函数是否发布、地址是否带 `https://` |
| 返回 `forbidden` | APP_KEY 不一致（网页端 key 与函数环境变量 APP_KEY 要一样） |
| 返回 `read fail 4xx` | GITHUB_TOKEN 没有写权限或已过期，去 GitHub 重新生成 |
| 返回 `write fail` | 网络波动，重试；或仓库被本地同步占用（等 1 分钟再试） |
| 语音按钮没反应 | iOS Safari 不支持语音识别，请用安卓 Chrome；或浏览器未授权麦克风 |
| 拍照识别慢 | 首次要下载 OCR 引擎（几秒到十几秒），之后有缓存会快 |

> ⚠️ 安全提示：中转站没有做限流，钥匙不要用太简单；令牌建议用仅限 `CET6-Dashboard` 仓库的 Fine-grained token，不要把有全局权限的令牌传上去。
